# feedpet.lua - CustomizedReply 脚本范例文档

## 📋 概述

`feedpet.lua` 是一个完整的 CustomizedReply 脚本范例，展示了如何编写一个功能完整的、生产级别的 Lua 脚本。该脚本实现了一个互动式的机器人投喂系统。

## 🎯 核心功能

### 1. 投喂机器人（MainProcess）
- 每次增加 1-50 的随机好感度值
- 将好感度数据持久化保存
- 返回格式化的反馈消息

### 2. 好感度等级系统
- 定义 3 个好感度等级（0-49, 50-99, 100+）
- 每个等级对应不同的回复和对话
- 支持灵活扩展到更多等级

### 3. 数据持久化
- 使用 `mod_storage_read/write` API 保存用户数据
- 本地缓存与持久存储同步
- `dispose()` 函数在 Mod 卸载时自动保存所有数据

### 4. 跨脚本通信
- 通过 `_script_registry` 导出 API
- 其他脚本可以调用本脚本的函数
- 实现模块化的脚本架构

## 📝 详尽注释新增内容

### 第一部分：生命周期函数

#### initial() 函数
```
【调用时机】脚本首次被执行时自动调用（且仅调用一次）

【主要职责】
  1. 初始化全局状态变量（缓存、标志位等）
  2. 加载持久化数据到内存中（可选）
  3. 向 _script_registry 注册 API 接口供其他脚本使用
  4. 初始化所需的常量、数据结构等

【最佳实践】
  ✓ 在此函数中初始化所有全局变量（_G.xxx）
  ✓ 在此函数中导出 API 到 _script_registry
  ✓ 避免在此处执行复杂计算或阻塞操作
  ✗ 不要在此处读取用户特定的数据，应在 MainProcess 中读取
```

#### dispose() 函数
```
【调用时机】Mod卸载时自动调用（且仅调用一次）

【主要职责】
  1. 保存所有状态数据到持久化存储（Mod Storage）
  2. 关闭文件句柄、数据库连接等资源
  3. 清理全局变量，释放内存
  4. 记录清理过程日志

【最佳实践】
  ✓ 在此函数中保存所有需要保持的状态数据
  ✓ 清理所有全局变量（_G.xxx = nil）
  ✓ 使用 try-catch 模式处理保存失败的情况
  ✗ 不要假设 dispose() 一定会被调用（如果程序崩溃可能不会调用）
```

### 第二部分：数据结构（AFFINITY_LEVELS）

每个好感度等级包含：
```lua
{
    min = 最小好感度,
    max = 最大好感度,
    response = "投喂时的反应字符串",
    conversations = { "对话1", "对话2", ... }
}
```

**扩展方法**：
1. 添加新等级：直接在表中添加新的等级配置
2. 修改回复：编辑 response 字段
3. 新增对话：在 conversations 数组中添加新字符串
4. 调整范围：修改 min 和 max 字段

### 第三部分：业务逻辑函数

#### MainProcess() - 主处理函数
```
【功能说明】
  实现完整的投喂流程：
  1. 读取用户当前的好感度
  2. 生成随机增长值 (1-50)
  3. 更新并保存新的好感度
  4. 获取好感度对应的等级反应
  5. 返回格式化的结果消息

【参数访问】
  • user_id: 当前用户的 QQ 号（数字）
  • group_id: 所在群组的 ID（数字）
  • message: 原始消息内容（字符串）

【错误容错】
  • 如果用户数据不存在，初始化为 100 点
  • 如果好感度超过上限，自动限制到 500
  • 如果没有匹配的等级，返回最后一个等级的回复
```

**代码步骤详解**：
1. 获取用户 ID 并初始化随机数生成
2. 从持久化存储读取当前好感度
3. 计算新的好感度并应用上限（500）
4. 保存新的好感度到持久化存储
5. 获取好感度对应的等级信息和回复
6. 构建并返回格式化的结果消息

#### GetAffinityInfo() - 等级查询函数
```
【功能说明】
  根据好感度数值查找对应的等级配置，返回该等级的信息
  这是一个通用的查询函数，被多个功能函数调用

【返回值】
  表：{ response: 等级回复, value: 好感度值 }

【错误处理】
  如果没有找到匹配的等级，返回最后一个等级信息
```

#### QueryAffinity() - 查询好感度
```
【功能说明】
  查询当前用户的好感度，返回详细的好感度信息和百分比

【返回值】
  格式化后包含好感度数值、百分比、等级反应的字符串
```

#### TalkToBot() - 对话函数
```
【功能说明】
  根据用户的当前好感度，从对应等级的对话池中随机选择一条对话
  实现"和我对话"的功能

【执行流程】
  1. 根据好感度找到对应等级的对话池
  2. 容错处理：找不到时使用最后一个等级
  3. 从对话池中随机选择一条
  4. 返回选中的对话字符串
```

## ⚡ 性能优化建议

1. **本地缓存**
   - 使用 `_G.affinity_cache` 缓存用户好感度
   - 减少 Mod Storage 的频繁访问

2. **批量保存**
   - 在 `dispose()` 中批量保存所有改动
   - 使用 `_G.cache_dirty` 标记改动状态

3. **随机数优化**
   - 使用组合种子确保不同用户的随机数不同
   - 避免重复的随机数序列

## 🔒 注意事项

1. **不要在 initial() 中读取用户数据**
   - initial() 只应初始化通用资源
   - 用户特定数据应在执行函数中读取

2. **不要假设 dispose() 一定被调用**
   - 程序异常退出时 dispose() 可能不会执行
   - 不应依赖 dispose() 进行关键的业务逻辑

3. **处理好感度不存在的情况**
   - 始终提供默认值（本脚本中为 100）
   - 避免 nil 引用错误

4. **验证数据范围**
   - 限制好感度在合理范围内（0-500）
   - 检查随机数的生成范围
