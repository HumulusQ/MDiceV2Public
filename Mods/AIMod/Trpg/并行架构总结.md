# TRPG AI 两部分并行结构总结

## 概述

当前系统存在两套并行的 NPC 管理架构：
- **旧系统**: NpcCanonicalState（基于本地规则推断）
- **新系统**: 四层架构（基于主模型标签驱动）

两套系统目前同时运行，功能有重叠但实现方式不同。

### 标签解析
**位置**: `PostProcessor.cs` - `ExtractFourLayerTags`

主模型通过以下标签驱动四层架构：

```csharp
<objective>目标描述</objective>              // 添加新目标
<complete>目标描述</complete>              // 标记目标完成
<abandon>目标描述</abandon>                // 放弃目标
<identity_merge>源名称->目标名称</identity_merge>  // 合并实体身份
<event>事件描述</event>                    // 记录新事件
<memory>记忆内容</memory>                  // 添加长期记忆
<entity_change>实体ID|新显示名称|新别名</entity_change>  // 更新实体信息
<scene_snapshot>场景描述</scene_snapshot>  // 创建场景快照
```

## 两套系统的对比

| 维度 | 旧系统 (NpcCanonicalState) | 新系统 (四层架构) |
|------|---------------------------|------------------|
| **数据来源** | 本地规则推断 | 主模型标签驱动 |

| **实体管理** | 单一 NpcId | EntityId + Aliases |
| **事件记录** | KeyEventsDigest 字符串 | 结构化 WorldEvent 列表 |

| **Prompt 集成** | BuildNpcIntegratedMemoryAsync | BuildContextAsync 四层数据 |
| **当前状态** | 仍在使用 | 已集成但未完全替代 |

## 功能重叠与差异

### 重叠功能

#### 1. 实体身份管理
- **旧系统**: `NpcCanonicalState.DisplayName`, `IdentityState`
- **新系统**: `EntityCanonicalRecord.CurrentDisplayName`, `IdentityStatus`
- **差异**: 旧系统更详细（包含关系状态），新系统更规范（支持别名合并）

#### 2. 事件记录
- **旧系统**: `KeyEventsDigest` (280 字符限制)
- **新系统**: `EventLog` 表 (无限历史，可查询)
- **差异**: 新系统支持按实体/场景/类型查询

#### 3. Prompt 集成
- **旧系统**: 【在场NPC统合记忆】
- **新系统**: 【在场实体】+【事件流】+【场景快照】
- **差异**: 新系统更结构化，信息更丰富

### 新系统独有功能

1. **目标管理**: Quest 表 + ObjectiveLayer
2. **场景快照**: SceneSnapshot 表 + SceneSnapshotManager
3. **实体合并**: identity_merge 标签
4. **事件查询**: 按实体/场景/类型查询

### 旧系统独有功能

1. **关系推断**: 基于关键词的自动关系变化检测
2. **关系累积**: PendingRelationshipDeltaJson + 阈值触发
3. **详细关系状态**: RelationshipState 字段

## 迁移建议

### 短期（保持并行）
- 两套系统继续并行运行
- 旧系统用于关系推断和 NPC 统合记忆
- 新系统用于目标、事件流、场景快照

### 中期（功能迁移）
1. 将关系推断迁移到新系统
   - 添加 `<relationship_change>` 标签
   - 在 EntityCanonicalRecord 中添加关系字段
2. 将 NPC 统合记忆迁移到新系统
   - 使用 EntityCanonicalRecord 替代 NpcCanonicalState
   - 保留关系累积机制

### 长期（完全迁移）
1. 废弃 NpcCanonicalState 表
2. 所有 NPC 管理通过四层架构完成
3. 关系推断改为主模型标签驱动
