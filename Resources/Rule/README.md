# Resources/Rule 规则文件目录

## 目录说明

此目录 `Resources/Rule` 用于存放所有游戏规则数据文件。程序启动时将自动扫描此目录，加载所有的规则数据到 RuleDataIO 数据库中。

## 支持的文件格式

### 1. JSON 文件 (推荐)

**文件扩展名**: `.json`

**格式**: 平面对象（Flat Object）结构，每个键对应一条规则说明

```json
{
  "关键词1": "规则说明文本1",
  "关键词2": "规则说明文本2",
  "关键词3": "规则说明文本3"
}
```

**示例** (`duel.json`):
```json
{
  "伤害": "伤害值 = 力量 + 武器加值。普通攻击伤害翻倍，暴击伤害翻三倍。",
  "防御": "防御 = (敏捷 + 防具加值) / 2，取整。",
  "生命值": "基础生命值 = 体质 × 10。游戏开始时双方生命值各为 100。"
}
```

### 2. SQLite 数据库文件

**文件扩展名**: `.db`

数据库文件中可以包含多个表，每个表将被加载为 RuleDataIO 中的一个规则表。

**表格式要求**:
- 列名: `key` (TEXT PRIMARY KEY), `value` (TEXT), `updated_at` (INTEGER, 可选)
- 每条记录表示一条规则

## 文件命名规则

### 表名标准化

文件名将被标准化处理：
1. 移除文件扩展名 (`.json` 或 `.db`)
2. 移除尾部的数字后缀 (`_1`, `_2` 等)

**示例**:
- `duel.json` → 表名: `duel`
- `duel_1.json` → 表名: `duel`
- `duel_2.json` → 表名: `duel` (若与上一个文件同表，会覆盖先前的数据)
- `default_rule.db` → 表名: `default_rule`

这样设计可以方便地分割大型规则文件，或同时维护多个版本。

## 加载流程

程序启动时执行以下步骤：

1. **创建目录**: 如果 `Resources/Rule` 不存在，自动创建
2. **扫描文件**:
   - 查找所有 `.db` 文件（排除 `.complete` 文件）
   - 查找所有 `.json` 文件（排除 `.complete` 文件）
3. **加载数据**:
   - 按字母顺序加载所有 `.db` 文件
   - 按字母顺序加载所有 `.json` 文件
   - 后加载的文件会覆盖先前加载的同名键值
4. **重命名文件**: 成功加载后，文件后缀改为 `.complete`
   - 防止下次启动时重复加载
   - 若要重新加载，删除 `.complete` 后缀即可
5. **记录日志**: 每个操作都会在系统日志中记录

## 防重复加载机制

已处理的文件会被重命名为 `.complete` 后缀：
- `duel.json` → `duel.json.complete`

这样设计的优点：
- 避免每次启动都重复加载相同的文件
- 保留原始文件的备份
- 若要重新加载，只需删除 `.complete` 后缀即可

## 使用场景

### 场景 1: 添加新的游戏规则

只需在此目录创建对应的 JSON 文件，重启程序即可：

```json
// mycustom_duel_mod.json
{
  "自定义规则1": "说明文本",
  "自定义规则2": "说明文本"
}
```

表名会自动标准化为 `mycustom_duel_mod`。

### 场景 2: 更新现有规则

删除对应的 `.complete` 文件，修改源文件内容，重启程序：

```bash
del duel.json.complete    # 删除标记文件
# 编辑 duel.json
# 重启程序，将重新加载
```

### 场景 3: 大型规则集分割

将规则分为多个 JSON 文件，自动合并到同一表：

```
duel_1.json → 表 duel
duel_2.json → 表 duel (覆盖/合并)
duel_3.json → 表 duel (覆盖/合并)
```

加载顺序：`duel_1.json` → `duel_2.json` → `duel_3.json`，后者覆盖前者。

## 错误处理

若某个文件加载失败：
- 系统会跳过该文件，继续加载其他文件
- 错误信息会记录在日志中
- **不会中断程序启动**

## 最佳实践

1. **文件编码**: 使用 UTF-8 编码（支持中文）
2. **JSON 格式**: 使用在线 JSON 验证工具检查语法
3. **文件大小**: 单个 JSON 文件建议不超过 1MB
4. **关键词设计**: 使用简短、易记的中文或英文关键词
5. **版本控制**: 在值的开头注明版本号便于追踪更新

## 技术细节

- **加载库**: System.Text.Json (.NET 内置)
- **数据库**: SQLite (基于 System.Data.SQLite)
- **冲突解决**: 基于加载顺序（后加载覆盖先加载）
- **并发安全**: 数据库使用 WAL 模式支持并发读写
- **内存效率**: 平面 JSON 对象结构最小化内存占用
